# OwnAgent 单客户试点运行手册

## 试点边界

- 周期：连续 14 天；5–10 名已授权办事员。
- 范围：报销对账、客服工单、门店排班，不开放其他技能。
- 数据：只使用客户正常业务导出的 CSV；禁止模板行、虚构案例和生产密钥进入测试记录。
- 每个技能至少完成 20 个真实案例，总样本至少 60 个。

## 启动门禁

1. `npm run check:production` 全部通过，私有部署清单可解析。
2. 客户域名 TLS、精确 CORS、入口身份控制和三种角色已验证。
3. 备份写入独立存储，并在干净环境完成一次恢复演练。
4. 办事员确认个人 Key 仅保存在当前浏览器，可一键清除。
5. 指定客户负责人、实施负责人、安全联系人和故障升级渠道。

## 每日记录

从受保护的 `/api/internal/metrics` 采集运行量、成功/失败、耗时和模型错误；工单系统另记以下不含业务正文的字段：

- 日期、匿名办事员编号、技能、是否完成、总耗时；
- 是否人工修正、修正次数、是否重新办理、是否归档；
- 模型供应商、调用次数和供应商账单费用；
- 问题级别（P0–P3）、现象、处理状态和根因类别。

不得记录个人 Key、CSV 正文、客户姓名、工单内容或可还原业务数据的截图。

## 每日检查

- 三技能完成量、核心流程成功率、P95、人工纠正率；
- LLM 401/429/超时与费用；
- SQLite 锁等待、磁盘余量、最近一次备份结果；
- P0/P1 问题与未关闭客户问题。

## 退出门槛

- 连续 14 天完成，5–10 名办事员实际使用；
- 三技能各至少 20 个真实案例；
- 核心流程成功率 ≥ 99%，无未关闭 P0 安全问题；
- 备份恢复演练通过，RPO ≤ 24 小时、RTO ≤ 4 小时；
- Key、日志、导出和备份抽查无敏感数据越界；
- 客户负责人书面确认可转生产。

任一门槛未满足，只能延长试点或修复后重新计量，不得宣称“已上线”。

## 结束交付

归档脱敏指标导出、问题清单、恢复演练记录、客户确认和上线/延期决定。删除临时账号与本地试点导出；按客户约定保留正式业务记录和审计记录。
