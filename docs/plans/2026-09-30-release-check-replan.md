# 发版检查重新规划

> 给实现用。先看「客户路径」，再看「功能放哪」，最后才是改哪些文件。

**Goal:** 发版检查页只回答一件事：这版能不能发给客户。其余能力保留，但不挡这条路。

**Architecture:** 技能详情五页签职责拆开。发版检查只展示结论 + 不一样的句子。问法编辑回「测试问题」。源码 diff、SCM、回流、压测、本页试跑收进一个「细看」折叠。底栏只留放弃 / 检查 / 发布。

**Tech Stack:** 现有 React 组件与 `runFullSkillCompare`，不新增引擎。

---

## 1. 这功能到底干什么

看改动只能看到「加了说法、改了步骤」。看不到的是：

- 客户那几句话，新版还会不会交给这个技能
- 新加的说法会不会抢走别人的话
- 处理步骤还是不是原来那样

所以发版检查是**用固定几句客户的话，把现用版和新版各跑一遍**。结论只有三种：

| 结论 | 客户理解 | 什么时候出现 |
| --- | --- | --- |
| 可以发 | 那几句回答没变 | 全部一样 |
| 先看一眼再发 | 有变化，但不一定坏 | 说法抢路、步骤变了但仍能答 |
| 先别发 | 会答错或答不出来 | 路由漂了且过不了、步骤挂了 |

一样的句子默认不列。不一样的句子才列，每句一句话说明「交给谁变了」或「步骤变了」，旁边一个「看看这句」。

如果页面做不到「一眼知道能不能发」，这功能就不如自己看改动。规划的验收标准就是这一句。

---

## 2. 现在乱在哪（不是功能多，是职责叠了）

技能详情现在有五页签，但「发版检查」把别人的活也干了：

| 页签 | 本该做什么 | 现在实际 |
| --- | --- | --- |
| 概览 | 看现用版是什么 | 还行 |
| 编辑 | 改草稿 | 还行 |
| 测试问题 | 维护必问句 | 有草稿时被发版检查吞掉，两处都能改句子 |
| 发版检查 | 告诉你能不能发 | 对比栏、问句表、逐句报告、试句双列、SCM、回流、压测、diff、底栏结论，全在一屏 |
| 版本记录 | 回滚 | 还行 |

同一份数据被画了多次：

- Gate 结论：色条、底栏、黄条同时说
- 问句：检查前一张表，检查后又一张表，技术折叠里还有一张
- 「只检查不发布」和「开始检查」抢同一个动作
- 试句结果在检查后自动铺开，把结论顶下去

`ReleaseWorkbench`、`ReleaseQuestionHub`、`CheckQuestions` 还在仓库里，`CheckView` 又重写了一套。三套入口，一套引擎。

## 3. 客户路径（发版检查页只走这一条）

**没检查时**

```
这次改了：新增说法「冒烟测试」
用 5 句客户的话对比两版。

                    [放弃草稿]  [检查]  [检查并发布]
```

不问法列表、不要左右两栏标签云、不要箭头、不要试句双列。

**检查中**

```
正在用 5 句对比现用版和新版…
这次改了：新增说法「冒烟测试」     ← 内容不消失
```

**检查完**

```
先看一眼再发
新加了说法「冒烟测试」，可能和别的技能抢同一句话。
5 句里 0 句回答变了。

这几句和现用版不一样          ← 仅当有不一样时出现
! 某某句    交给的技能变了    [看看这句]

▸ 改要测的句子（5）
▸ 细看（源码、回流、压测、本页试跑）

                    [放弃草稿]  [重新检查]  [发布]
```

点「看看这句」才在该行下方展开现用/新版对比。检查本身不再自动铺一块对比。

## 4. 每样功能放哪（全部保留，换位置）

**发版检查主屏（默认看见）**

- 改了什么：一到三条人话
- 结论：可以发 / 先看一眼 / 先别发 + 一句原因
- 不一样的句子（没有就不出现）
- 底栏：放弃、检查、发布

**「改要测的句子」折叠（仍在发版检查，默认收起）**

- 必问句列表、加上、删除、本周问过收进必问
- 检查前和检查后共用这一处，不再因有没有报告切换两套 UI

**「细看」折叠（仍在发版检查，默认收起）**

- 源码逐行 diff
- FullCompareReport（隐藏逐句表，主屏已经有）
- 回流、邻域压测、本页试跑（`ReleaseCheckExtras`）
- 影响范围（新接手 / 不再接手）
- 依赖证明（仅 release-inspector）
- SkillBreakPanel、PageToolWalk

**「测试问题」页签**

- 只维护问法，不跑全量检查
- 有草稿时不要再把整个 CheckView 嵌进来
- 需要检查时，页内一个按钮切到「发版检查」

**对话里**

- 「对话验收」只在结论不是「先别发」时出现在底栏
- 不在主屏再放一遍

**导出 MD / JSON**

- 放进「细看」折叠，不和结论抢位置

---

## 5. 底栏规则（固定窗口底部，不跟内容长短走）

发版检查页底栏永远是：

- 左：放弃草稿
- 中：检查 / 重新检查 / 检查中…
- 右：检查并发布 / 发布（先别发时禁用发布）

不要在底栏重复写「检查结果：先看一眼再发」。结论只在主屏顶部出现一次。

编辑页底栏可以保留草稿行数、自动保存。发版检查页不要那行工程师状态。

## 6. 实现时改哪些文件

1. `SkillComparePanel.tsx` 的 `CheckView`
   - 主屏只保留：改了什么、结论、不一样的句子
   - 问法列表始终在一个 details 里
   - 技术块合并成一个「细看」details
   - 检查完成不要 `setSingle`，避免自动铺对比
   - `tab === "cases"` 有草稿时不要渲染 CheckView，只渲染 `ScmCaseEditor`

2. `SkillComparePanel.tsx` 底栏
   - `own-ver-sticky--rel` 只留三个按钮
   - 发版检查页隐藏 `own-skm-bar-status`

3. `styles.css`
   - 主屏：结论区、改动列表、问题句
   - 底栏继续 `position: fixed` 贴工作区底

4. 不删引擎
   - `runFullSkillCompare`、回流、fuzz、pageWalk、depProof 照跑
   - 只是默认不展开渲染

5. 死代码（实现稳定后再清）
   - `ReleaseWorkbench`、`ReleaseQuestionHub` 若已无引用，删除或标明废弃
   - 不要同时维护三套发版 UI

---

## 7. 怎么算做对了

打开有草稿的技能 → 发版检查：

1. 第一眼能读完「改了什么」，底下三个按钮能点检查
2. 检查完第一眼是结论，不是问句表也不是技术折叠
3. 全部一样时，页面上没有逐句清单
4. 有不一样时，只列出那些句，点一句才展开对比
5. 底栏钉在窗口底，滚动内容时仍在底
6. 「测试问题」只改句子，不再出现完整发版检查页
7. 细看里仍能导出、看回流、看 diff、看 SCM

客户不用这个功能的唯一理由，应该是「我还没改完」，而不是「这页我看不懂」。
