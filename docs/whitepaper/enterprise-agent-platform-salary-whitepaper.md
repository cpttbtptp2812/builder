## 🟡 第二档：25K-30K — 工业级落地加固（经得住代码现场追问）

> **目标：不搞花里胡哨的虚浮概念，不要求先上 Milvus 集群，但每一处代码都能抗住真实业务追问，能够现场在白板上画出完整的数据流与调用链。**

### 1. 六大真实落地硬指标（必须指着代码说）

#### ① 入库流水线与切片可解释性
- **长文本切片工程**：一份长文档上传，按固定长度（如 500 字符）加重叠（Overlap 如 50 字符）切分，必须存入 `knowledge_chunk` 表，记下属于哪篇文档、第几片；
- **向量入库离线化**：向量在入库保存时算完并写入 `embedding_json` 字段，**搜索检索时绝不能对每篇文章现算 Embedding**；
- **切片可视化与边界把控**：页面上直观看到文档切了多少片、哪一片处理失败；**PDF 和 Word 做不了就不要留入口**（仅支持 Markdown/TXT），实事求是；
- **面试必问防御**：“*切片多大？重叠多少？切在句子中间怎么办？*”  
  - **代码回答**：“我们设置 Chunk Size 为 500 字符，Overlap 为 50 字符。分块算法优先按照段落换行符 `\n\n` 和句号 `。` 寻找语义切分断点；如果超长则硬截断，50 字符重叠窗口确保跨块实体与上下文语义不丢失。”

#### ② 真实 RAG 检索进回答并带来源溯源
- **切片真正进入 Prompt**：知识库测试台单独能搜不等于对话 RAG。用户在对话里提问时，后台命中的 Top-K 切片必须动态拼装进 System Prompt 上下文中；
- **相似度硬阈值拒答**：设定相似度阈值（如 `< 0.65`），低于阈值的噪音切片坚决丢弃，不塞进提示词；未命中有效切片时，降级为通用常识回答，杜绝模型幻觉；
- **前端溯源角标**：回答内容旁边必须能展示本次回答引用了哪几篇文档、第几个切片以及相似度得分。

#### ③ 对话里的工具调用形成完整闭环与自愈
- **三步调用闭环**：模型返回 `tool_calls` -> Spring Boot Java 反射执行本地逻辑 -> 将结果作为 `role: tool` 消息喂回模型 -> 模型汇总生成最终自然语言；
- **递归守卫**：硬编码限制单次任务最大递归深度 <= 3 次，防止死循环烧钱；
- **异常自纠错（Self-Correction）**：大模型生成参数缺失或类型不合法时，不要直接抛 500，将校验错误包装成工具消息退回给大模型让其纠错重试；数据库插件严格执行只读查询（SELECT），杜绝未授权写操作；
- **全链路审计**：每一次工具调用记录到审计表：工具名、入参 JSON、耗时、状态（成功/失败）。

#### ④ 上下文边界与真假记忆
- **边界控制**：选中的智能体提供 System Prompt；历史上下文只带最近 N 轮（如最近 3 轮），超长按规则滑动丢弃，说得清截断边界；
- **剔除假记忆**：启动时写在内存里固定的“客户架构偏好”必须剔除，要么不做，要么通过后台任务从用户真实对话中提炼出真实偏好事实存库。

#### ⑤ 检索算法：先缩小范围，再算余弦（两阶段召回）
- **性能防线**：坚决避免每次搜索都 `findAll` 并在当前请求中临时现建倒排索引；
- **工程解法**：通过 BM25 关键词匹配先从数据库中粗筛出 Top 50 候选集，**只对这 50 个候选切片读取预存的 `embedding_json` 并在内存中计算余弦相似度**；
- **架构演进说明**：“*为什么不上 Milvus？* 经过压测，在单机 5000 篇切片以内，BM25 粗筛 + 内存余弦计算耗时稳定在 30ms 以内，完全不需要维护沉重的分布式向量库；当切片规模突破 5 万篇时，再平滑演进到 PGVector (HNSW 索引) 或独立向量库。”

#### ⑥ 答到代码上的并发与线程模型
- **客户端断开物理级 Cancel**：前端一键 Stop 或连接断开（`onCompletion` / `onTimeout`），后端捕获信号后立即 Cancel 与上游公网模型的 HTTP 物理连接，停止计费；
- **Tomcat 线程释放**：采用 Spring Boot 异步流式处理，耗时等待发生在 I/O 线程池，Tomcat 请求工作线程即刻归还，防止大模型慢请求打满 Tomcat 线程池导致整站 504；
- **Token 账单防虚标**：若上游接口未返回真实 `usage`，审计日志绝不显示虚假账单数据。

### 2. 现场常考白板演练重点
1. **画离线与在线两条线**：
   - **离线线**：文档上传 -> 正则/标点语义切片（Chunk + Overlap） -> 调 Embedding API 批量向量化 -> 写入 `knowledge_chunk (content, embedding_json)`。
   - **在线线**：用户提问 -> BM25 粗筛候选 -> 内存余弦精排 -> RRF 归一化融合 -> 阈值过滤 -> 注入 Prompt Context -> SSE 异步推流 -> 携带引用角标。
2. **写出工具调用消息结构**：
   - 清楚写出 `messages` 中从 `user` -> `assistant(tool_calls)` -> `tool(result)` -> `assistant(final)` 的完整传递结构。
3. **BM25 参数用代码里的数讲**：
   - 讲清公式中的 $k_1 = 1.2$（控制词频饱和度）、$b = 0.75$（惩罚长文本切片长度）和 IDF 计算逻辑。
