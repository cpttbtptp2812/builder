# 门店排班

把**员工表**（谁会做什么、哪天能上、几点到几点、周工时上限、时薪、请假）和**班次需求表**（哪天哪个班要几个什么岗位的人）交给它，它会在贵司的用工规则下把人排上去：先排最难排的班，排不满的再试着调换补上，排完逐人逐班复核一遍规则，最后算出每人工时、加班、夜班和人工成本，排不上的班写清楚为什么排不上。

所有排班结果、工时和金额都由程序算出；大模型只负责把排班结果写成一份发到门店群里的通知，不增删班次、不改时间。没有配置大模型时，照样办结，只是没有通知稿。

## 一、需要哪些材料

### 1. 员工表（必需）

一行一人。列名不必一字不差，括号里是能认出来的别名：

| 标准列 | 必需 | 能认的写法 | 说明 |
| --- | --- | --- | --- |
| 员工 | 是 | 姓名、店员、人员、name | 重名只保留第一行 |
| 岗位技能 | 是 | 技能、可做岗位、会做、岗位、skill | 一人多岗用竖线、顿号或逗号分隔，例如「收银、理货」；要和班次需求表的岗位名一致 |
| 用工类型 | 否 | 合同类型、雇佣、类型 | 全职、兼职、非全日制、实习等；决定默认的周/日工时上限 |
| 周工时上限 | 否 | 工时上限、每周最多小时、max hours | 填了以员工表为准，没填按用工类型 |
| 可上班星期 | 否 | 可排班、星期、周几、出勤日 | 见下方写法；空着 = 每天都可以 |
| 最早 | 否 | 最早到岗、earliest | 例如 `07:00`；空着 = 不限 |
| 最晚 | 否 | 最晚离岗、latest | 例如 `22:00`；写 `24:00` 表示可以上跨夜班；空着 = 不限 |
| 时薪 | 否 | 小时工资、每小时、单价、rate | 元/小时；没填的人成本按 0 计，并在结果里点名 |
| 不可用日期 | 否 | 请假、休假、不能上、例休 | 多个日期用竖线或逗号分隔；区间写 `2026-10-20~2026-10-22` |

**可上班星期的写法**：`周一至周五`、`周二到周六`、`周六|周日`、`一三五`、`1-5`、`每天`、`全周`、`不限`。区间可以跨周末，例如 `周五至周一` = 周五、周六、周日、周一。

### 2. 班次需求表（必需）

一行一个班次的一个岗位：

| 标准列 | 必需 | 能认的写法 | 说明 |
| --- | --- | --- | --- |
| 日期 | 是 | date、日 | `2026-10-19`、`2026/10/19`、`2026年10月19日` |
| 班次 | 否 | 班别、班名、shift | 早班、晚班、午高峰等，只用于显示 |
| 开始 | 是 | 上班时间、起始、start | `07:00` |
| 结束 | 是 | 下班时间、截止、end | `15:00`；结束早于开始表示跨夜，例如 `22:00`—`06:00` |
| 岗位 | 是 | 技能、职位、工种、role | 和员工表的岗位技能对应 |
| 人数 | 是 | 需求人数、需要、数量、headcount | 正整数 |

同一个班次需要两个岗位（例如早班要 2 个收银、1 个理货）写两行。

### 3. 下载模板

导入面板里可以下载两份模板，表头就是上面的标准列，模板里的几行只是格式示例，**请换成门店真实的员工名单和班次需求再办理**。

### 4. 从现有系统导出

- **钉钉 / 飞书 / 企业微信考勤**：员工表可以从「通讯录」或「人员档案」导出姓名、岗位，再补上可上班星期、最早/最晚和时薪；班次需求按门店的「排班规则」或人力预测整理成一行一个班次岗位。
- **门店 POS / 客流系统**：按小时客流或交易笔数估算每个时段需要几个收银，整理成班次需求表的「人数」。
- **Excel 手工表**：横向「日期 × 班次」的排班模板请先转成一行一个班次岗位（日期、班次、开始、结束、岗位、人数）再导入。
- 导出后用 Excel 另存为 CSV（UTF-8 或 GBK 都可以），列名不必改。

## 二、处理流程（每一步做什么、规则在哪改）

技能是一串有先后的处理步骤，后一步用前一步的结果。删掉「调换补缺」，缺口就只靠初排；删掉「统一岗位名」，「收银员」和「收银」就会被当成两个岗位；删掉「复核规则」，就不会在发布前再检查一遍。

### 1. 读入员工 `__shift_staff__`

- 解析岗位技能、可上班星期、最早/最晚、时薪、请假日期。
- 姓名为空、重名、没填岗位技能、可上班星期看不懂的员工**不参与排班**，并记入数据问题。
- 时薪、周工时上限、请假日期看不懂的，记入数据问题，但人仍然参与排班（按没填处理）。
- 一个可排的员工都没有时停下。

### 2. 读入班次 `__shift_demand__`

- 结束时间早于或等于开始时间的按跨夜班处理（结束在第二天）。
- 日期、时间、人数看不懂，或班长超过 16 小时的行不参与排班。
- `maxSeats`：一次最多排多少人次（所有行人数之和）。超过请按周拆开导入。

### 3. 统一岗位名 `__shift_roles__`

员工表是人事维护的，班次需求是店长写的，同一个岗位经常有好几种写法。这一步在排班前把它们统一：

- `aliases`：左边的写法统一成右边，例如 `收银员: 收银`。员工表的岗位技能和需求表的岗位都会替换。
- `ignoreSuffix`：先去掉这些后缀再比对，例如「收银岗」「理货组」。
- 统一了哪些写法会列成一张小表（原写法 / 统一为 / 出现在哪张表），方便您确认没有统一错。

注意：别名是双向生效的——如果把「副店长」统一成「值班长」，那么会做「值班长」的班次，副店长也能上。

### 4. 检查数据 `__shift_validate__`

- 汇总员工表和班次需求表里的所有问题，出「数据问题」表。
- 列出**没有任何员工会做**的岗位——这类班次一定排不上。统一岗位名之后还剩下的，通常是员工表漏填了技能，或需求表写错了岗位。
- 看不懂的班次占比超过 `maxBadRatio` 时停下。

常见问题与修法：

| 提示 | 常见原因 | 修法 |
| --- | --- | --- |
| 看不懂可上班星期 | 写成了「工作日」「双休」之类 | 改成「周一至周五」「周六、周日」或「每天」 |
| 看不懂最早/最晚时间 | Excel 把 `07:00` 存成了 `0.2916` | 单元格格式改成文本后重新输入 |
| 看不懂日期 | 日期被存成数字 `46315` | 单元格格式改成日期 `yyyy-mm-dd` 再另存 |
| 人数不是正整数 | 写了「1人」「两人」或小数 | 只写数字 |
| 班长超过 16 小时 | 开始、结束写反，或少写了跨夜 | 检查开始和结束 |
| 没有员工会某岗位 | 员工表漏填技能，或写法差异没有被统一 | 在员工表补技能，或在「统一岗位名」加别名 |
| 员工重名 | 同名两人 | 姓名后加工号区分，例如「李娜-0231」 |

### 5. 用工规则 `__shift_rules__`

| 参数 | 含义 | 默认 |
| --- | --- | --- |
| `minRestHours` | 两个班之间（上一个班下班到下一个班上班）至少休息几小时 | 11 |
| `maxDailyHours` | 每天最多计薪几小时 | 10 |
| `maxShiftsPerDay` | 每天最多几个班 | 1 |
| `maxConsecutiveDays` | 最多连续上几天 | 6 |
| `minRestDaysPerWeek` | 每周（周一到周日）至少休息几天 | 1 |
| `weeklyCapByType` | 按用工类型的周工时上限 | 全职 40、兼职 24 |
| `dailyCapByType` | 按用工类型的日工时上限（取它和 `maxDailyHours` 中较小的） | 兼职 4 |
| `defaultWeeklyCap` | 类型也匹配不上时的周上限 | 40 |
| `overtimeAfterWeeklyHours` | 一周超过多少小时的部分算加班 | 40 |
| `overtimeRate` | 加班倍数 | 1.5 |
| `breakAfterHours` / `breakMinutes` | 班长超过几小时扣多少分钟用餐（不计薪） | 6 小时 / 30 分钟 |
| `nightStart` / `nightEnd` / `nightPremium` | 夜班时段与津贴比例 | 22:00—06:00 / 0.2 |
| `nightShiftMinMinutes` | 落在夜班时段里至少多少分钟才算一个夜班 | 120 |
| `maxNightShiftsPerWeek` | 每人每周最多几个夜班，0 = 不限 | 3 |
| `holidayPayDays` / `holidayPayRate` | 法定节假日与当天计薪倍数 | 2026 年 13 天 / 3 倍 |
| `minWeeklyHoursByType` | 按用工类型的保底周均工时（只提醒，不强排） | 全职 32 |

说明：

- **周**按周一到周日算（ISO 周），跨周的排班分别累计。
- **计薪工时** = 班长 − 用餐扣除；日上限、周上限、加班、节假日工时都按计薪工时算。
- 员工表里填了「周工时上限」的以员工表为准；没填的按「用工类型」包含的字匹配 `weeklyCapByType`。
- 非全日制用工按劳动合同法第六十八条每天不超过 4 小时、每周累计不超过 24 小时，默认已经配好；如果贵司的兼职是全日制劳动合同，请把 `dailyCapByType` 里的「兼职」删掉。
- `maxShiftsPerDay` 改成 2 时，同一天的两个班之间不受 `minRestHours` 限制（典型的「两头班」），但两个班加起来仍不能超过日上限。
- `minRestDaysPerWeek: 1` 对应劳动法第三十八条「每周至少休息一日」；实行综合计算工时的岗位可以改成 0，由连续上班天数控制。
- `holidayPayDays` 只填**法定节假日**本身（2026 年共 13 天），调休放假的那几天属于休息日，不在里面；休息日上班一般安排补休，不另计倍数。
- 2026 年法定节假日：元旦 1 月 1 日；春节 2 月 16 日至 19 日（除夕至初三）；清明 4 月 5 日；劳动节 5 月 1 日、2 日；端午 6 月 19 日；中秋 9 月 25 日；国庆 10 月 1 日至 3 日。**请按当年国务院公布的安排核对。**

### 6. 筛人选 `__shift_eligibility__`

对每个班次，先排除**不管怎么排都不能上**的人：

- 不会这个岗位；
- 当天请假（跨夜班还要看第二天）；
- 那天是他不上班的星期；
- 班次开始早于他的「最早」，或结束晚于他的「最晚」（「最晚」写 `24:00` 的人可以上跨夜班）。

剩下的就是这个班的候选人。这一步会列出最难排的几个班（要的人多、能上的人少）。

### 7. 初排 `__shift_assign__`

把每个班拆成「人次」（要 2 个人就是 2 个位置），按 `order` 排序后逐个位置挑人：

- `order: scarcity`：候选人数 ÷ 需要人数 最小的位置先排。难排的班先占人，能明显减少缺口。
- `order: chronological`：按时间先后排，简单直观，但后面的班更容易出缺口。

每个位置从候选人里挑**排上去不违反任何规则**的人：

- 同一个班次不重复排同一个人；
- 和他已有的班时间不重叠；
- 和前后班之间休息 ≥ `minRestHours`；
- 当天班数 < `maxShiftsPerDay`，当天计薪工时 + 本班 ≤ 他的日上限；
- 本周计薪工时 + 本班 ≤ 他的周上限；
- 排上后连续上班天数 ≤ `maxConsecutiveDays`；
- 本周上班天数 ≤ 7 − `minRestDaysPerWeek`；
- 如果本班是夜班，本周夜班数 < `maxNightShiftsPerWeek`。

多人都符合时按 `tieBreak`：

- `fair`：已排工时 ÷ 周上限 最小的人优先，其次时薪低的，再其次员工表顺序。结果是工时更均衡。
- `cost`：时薪低的优先，其次已排工时少的。结果是成本更低，但工时会集中在少数人身上。

### 8. 调换补缺 `__shift_repair__`

初排后还空着的位置，逐个尝试：

1. 先看有没有候选人现在可以直接补上（初排时因为别的班占着而没排他，后来情况变了）；
2. 再试一层调换：找一个会这个岗位、但因为已经排了某个班 A 而不能上的人 X；如果把 X 从 A 换下来他就能补这个缺口，并且能找到另一个人 Y 顶上 A，就把 X 调过来、让 Y 去上 A。

每次调换都会记一行「补上的班 / 调过去的人 / 原来的班 / 原来的班改由谁」，排班表里调换过的人会标「（调换）」。`maxSwaps` 限制最多调换次数。

调换只换一层（X 让出 A、Y 顶上 A），不会连环调换；所以这一步补不上的缺口，基本说明在现有规则下人手确实不够。

### 9. 复核规则 `__shift_verify__`

排完以后**逐人逐班**把第 6、7 步的所有规则重新检查一遍。正常情况下应该是 0 处违规；如果出现违规（例如规则步骤在初排之后被改动过），会停下并列出违规明细，不让有问题的排班表发出去。

### 10. 工时成本 `__shift_hours__`

每人：

- 班数、计薪工时、最忙一周的工时、周均工时；
- 加班工时 = 每周超过 `overtimeAfterWeeklyHours` 的部分之和；
- 夜班工时 = 班次落在夜班时段里的小时数；夜班数 = 夜班时段内满 `nightShiftMinMinutes` 的班数；
- 周末班 = 排在周六、周日的班数；
- 节假日工时 = 排在 `holidayPayDays` 里的计薪工时；
- 预计成本 = 计薪工时 × 时薪
  + 加班工时 × 时薪 × (加班倍数 − 1)
  + 夜班工时 × 时薪 × 夜班津贴比例
  + 节假日工时 × 时薪 × (节假日倍数 − 1)。

同时给出合计工时、合计加班、节假日工时、合计成本，以及工时最多与最少的人相差多少。

### 11. 缺口分析 `__shift_gaps__`

对每个没排满的班，把会这个岗位的人逐个过一遍，统计他们为什么上不了：

- 当天请假 / 那天不上班 / 时段不合适（筛人选阶段排除的）；
- 时段冲突 / 两班之间休息不足 / 当天已有班 / 超出每日工时上限 / 超出周工时上限 / 连续上班超限 / 每周休息日不足 / 本周夜班次数已满（规则限制的）；
- 能上但已排到更难排的班（人手本身不够）。

例如「会收银的 5 人里：2 人当天请假，2 人超出周工时上限，1 人两班之间休息不足」。看到这里就知道该补人、该调整需求，还是该放宽某条规则。

### 12. 覆盖率检查 `__shift_coverage_guard__`

- 覆盖率 = 排上的人次 ÷ 需要的人次。低于 `minCoverage` 时提醒。
- `criticalRoles` 里的岗位只要有一个班没排满就提醒。
- 默认 `guard: warn` 只提醒、照常出表；改成 `guard: fail` 并加上 `failFast: true` 则直接停下，不出排班表。

### 13. 开闭店检查 `__shift_keyholder__`

门店每天开门和关门都要有能负责的人：持钥匙、开关收银机、清点交接备用金。这一步对每一天：

- 找出最早开始的班次时刻（开店）和最晚结束的班次时刻（闭店）；
- 看那一刻在班的人里有没有人具备 `keySkills` 里的任一岗位技能（默认店长、值班长）；
- 没有就列出来：日期、开店或闭店、当时在班的是谁。

员工表里一个具备这些技能的人都没有时，直接提醒。`checkOpen` / `checkClose` 可以只查一头。默认只提醒（`guard: warn`）；要求必须满足才能发布，改成 `guard: fail` 并加 `failFast: true`。

### 14. 均衡检查 `__shift_fairness__`

只在同一用工类型（`compareType`，默认全职）之间比较：

- 计薪工时最多与最少相差超过 `maxHoursSpread` 小时；
- 周末班最多与最少相差超过 `maxWeekendSpread` 个；
- 有人周均工时低于 `minWeeklyHoursByType` 的保底。

任一条命中就提醒并写明是谁。保底工时只提醒不强排：门店需求本身不够时，硬塞班会造成人力浪费，应由店长决定是否调班或调整需求。

### 15～18. 交付表格

| 步骤 | 表 | 内容 |
| --- | --- | --- |
| `__shift_deliver_roster__` | 排班表 | 每个班次一行：日期、星期、班次、时间、岗位、需要、已排、人员、缺口、计薪工时 |
| `__shift_deliver_matrix__` | 人员日历 | 每人一行、每天一列：上什么班，或「休」「请假」 |
| `__shift_deliver_person__` | 个人工时表 | 每人班数、计薪工时、周上限、最忙一周、周均、保底、加班、夜班工时与夜班数、周末班、节假日工时、时薪、预计成本、上班日 |
| `__shift_deliver_gaps__` | 缺口清单 | 没排满的班、缺几人、为什么排不上 |

哪一步不在技能里，文书里就没有那张表。每张表都可以单独下载成 CSV。人员日历适合直接打印贴在门店；排班表适合导回考勤系统。

### 19. 结论 `__shift_report__`

一句话：需要多少人次、排上多少（覆盖率）、缺多少、调换补上几个、合计计薪工时与加班、预计人工成本、复核结果。同时整理每人班表和缺口给下一步。

### 20. 排班通知 `__llm_product_brief__`

- 用已配置的大模型，按 `role` / `task` 把每人班表写成一份门店群通知。
- `lockNumbers: false`：通知不要求复述成本等统计数字；但人名、日期、时间、岗位只能照抄程序给的班表。
- `keepEngineLine: true`：办结说明 = 程序结论 + 通知稿。
- 没配置大模型：这一步跳过；配置了但调用失败：这一步报错并写明原因。

## 三、常见调整示例

**允许两头班**：`maxShiftsPerDay: 2`，`maxDailyHours` 保持 10。

**更省钱**：初排和调换补缺的 `tieBreak` 都改成 `cost`。

**连续上班不超过 5 天**：`maxConsecutiveDays: 5`。

**每周双休**：`minRestDaysPerWeek: 2`。

**夜班没有津贴**：`nightPremium: 0`。

**不限夜班次数**：`maxNightShiftsPerWeek: 0`。

**没排满就不出表**：覆盖率检查改成 `guard: fail`，加 `failFast: true`。

**咖啡岗也必须排满**：`criticalRoles` 加一行 `- 咖啡`。

**开店必须是店长本人**：开闭店检查的 `keySkills` 只留 `- 店长`。

**新增一种岗位写法**：在「统一岗位名」的 `aliases` 加一行，例如 `点单员: 收银`。

改完先在技能页「用材料试跑」，用同一份员工表和班次需求对比改前改后：覆盖率、缺口、成本、谁的班变了，一目了然。

## 四、停下来的情况

| 停在哪一步 | 原因 | 怎么办 |
| --- | --- | --- |
| 读入员工 / 读入班次 | 还没导入材料，或没有一行能看懂 | 导入员工表和班次需求表后点继续 |
| 检查数据 | 看不懂的班次太多 | 按数据问题表修正，常见是时间被 Excel 改成小数 |
| 复核规则 | 排班结果违反规则 | 看违规明细；通常是步骤顺序被改动，恢复「用工规则」在「初排」之前 |
| 覆盖率检查（fail 时） | 覆盖率不够或关键岗位缺人 | 看缺口清单的原因，补人或调整需求 |
| 开闭店检查（fail 时） | 开店或闭店没有持钥匙的人 | 给对应日期补排店长/值班长，或给员工表里能负责的人加上技能 |
| 排班通知 | 大模型调用失败 | 看报错原因检查接入配置；排班表不受影响 |

步骤顺序被改乱（例如删了「用工规则」却保留「初排」）时，会提示「这一步需要先完成某某步骤」。

## 五、口径说明

- 排班是确定性的：同样的员工表、需求表和规则，任何时候排出来的结果都一样，便于复核和版本对比。
- 初排是贪心算法加一层调换，不保证全局最优，但每一个排上去的班都满足所有硬规则，排不上的会写明原因。
- 跨夜班算在开始那天：日上限、连续天数、星期、节假日都按开始日期判断，请假会同时看第二天。
- 夜班津贴按班次落在夜班时段内的实际分钟数算，不扣用餐。
- 加班按周算，不按天算；一周内某天超过 8 小时但周合计不超过 40 小时的，不计加班（与标准工时制下按日计加班的口径不同，实行标准工时制的门店请按贵司制度复核）。
- 没填时薪的人成本按 0 计并点名，合计成本会偏低。

## 六、常见问题

**为什么兼职排不上 8 小时的班？**
默认 `dailyCapByType` 给兼职（非全日制）设了每天 4 小时上限。需求表里给兼职安排的应是 4 小时以内的高峰班；如果贵司兼职签的是全日制合同，把这一行删掉即可。

**为什么有人工时明显偏少？**
看个人工时表的「可上班星期」「最早/最晚」是否限制太多，或请假日期较多；再看均衡检查的提醒。`tieBreak: fair` 会优先给工时占比低的人，但候选人受硬规则限制时也无能为力。

**同一个人周日晚班、周一早班为什么排不上？**
两班之间休息不足 `minRestHours`。例如 22:00 下班、次日 07:00 上班只休息 9 小时，小于 11 小时。

**为什么排班表里有人标了「（调换）」？**
这个人原本排在别的班，为了补上一个缺口被调了过来，原来的班由另一个人顶上。调换记录在「调换补缺」这一步的明细里。

**需求跨两周可以一起排吗？**
可以。周上限、加班、每周休息日、夜班次数都按周一到周日分别计算，连续上班天数会跨周累计。

**为什么结果和上次不一样？**
排班是确定性的，结果变化只可能来自材料或规则变化：员工表或需求表改过、技能版本不同。在技能页用同一份材料试跑两个版本，可以看到具体哪一步不同。

## 七、发布排班前怎么看结果

建议店长按这个顺序过一遍再发到群里：

1. **结论那一句**：覆盖率是否达标、缺几人次、复核是否无违规。复核有违规时不要发布。
2. **缺口清单**：每个缺口的原因。
   - 「没有员工会某岗位」→ 招人或培训；
   - 「当天请假」占多数 → 和请假的人确认能否调休；
   - 「超出周工时上限」占多数 → 人手不够，考虑临时工或减少需求；
   - 「两班之间休息不足」占多数 → 晚班接早班的排法太密，考虑调整班次时间。
3. **开闭店检查**：每天开店、闭店都有能负责的人。
4. **人员日历**：逐人看一眼，有没有本人事先说过不方便的安排（这类口头约定请补进员工表的不可用日期，下次就会自动避开）。
5. **个人工时表**：加班工时、节假日工时、预计成本是否在预算内；低于保底的人是否需要补班。
6. **均衡检查**：工时和周末班是否明显不均。

确认后下载排班表导入考勤系统，人员日历打印张贴，排班通知发到门店群。
